# PairCode IDE 桌面端（wb-ui 原生窗口）

> 交付日期：2025-09-25　引擎：wb-ui（自研 WebKit + Skia，非 Chromium/Electron）

## 形态

| 文件 | 作用 |
|---|---|
| `gouide-desktop.exe` | **桌面端外壳**（GUI 子系统，无控制台窗）。原生窗口 + wb-ui 渲染引擎 |
| `pair.exe` | PairCode 内核后端（同目录，被外壳自动拉起） |
| `libSkiaSharp.dll` | Skia 原生渲染库（外壳依赖，必须与 exe 同目录） |
| `启动桌面端.cmd` | 一键启动（等价于双击 `gouide-desktop.exe`） |

## 使用

1. 双击 `gouide-desktop.exe`（或 `启动桌面端.cmd`）。窗口标题默认 **`PairCode IDE`**
   （由 `-title` 决定；启动脚本不传该参数，故双击得到的标题就是 `PairCode IDE`）。
2. 外壳会在**后台自动拉起**同目录的 `pair.exe`（隐藏控制台窗口，端口 **9098**，绝不占用 Web 模式默认端口 9090），
   轮询 `/api/system/info` 就绪后加载界面。
3. 关闭窗口 → 外壳一并结束后端进程。

## 命令行参数

```
gouide-desktop.exe [-port 9098] [-width 1600] [-height 1000] [-title "PairCode IDE"]
                   [-backend <pair.exe 路径>] [-attach] [-keep-alive]
                   [-headless [-frames 90] [-out shot.png] [-eval <js>] [-dump-text]]
```

- `-attach`：只连接已在运行的后端（不再拉起新进程）
- `-keep-alive`：窗口关闭后保留后端服务
- `-backend`：显式指定后端可执行文件（缺省按「同目录 pair.exe/companion.exe → 同目录 bin/ → PATH」自动发现）
- `-headless`：无窗口自检（不建窗口，加载页面后打印摘要/可截图），用于自动化验证
- `-eval` / `-dump-text`：诊断入口（执行页面 JS / dump 渲染树文本对象）

- Windows x64
- `libSkiaSharp.dll` 与 `gouide-desktop.exe` 同目录（Windows 会从 exe 所在目录加载 DLL）
- 若单独运行（不经启动脚本），无需设置 PATH

## 已修复的引擎缺陷（本轮，均在 wb-ui 仓）

1. **注释被当作按钮文字绘制**：`engine/dom/node.go` 的 `TextContent()` 容器分支把注释(Comment)数据一并拼接
   （违反 DOM 规范：容器只拼接 Text 节点后代）→ `renderformcontrol.go` 的 `paintButtonText` 用
   `el.TextContent()` 当按钮文字 → 图标按钮 `<button><svg><!-- Folder -->…</svg></button>` 把注释原文
   画在图标上（界面出现 `Folder`/`Chevron Down (Rotated chevron-right)` 等文字污染）。
2. **窗口渲染循环不执行动态资源队列**：`flushDynamicScripts()` 只被 `WebView.Render()` 调用，
   而窗口循环 `app.Host.Run()` 走 `processEvents → EnsureLayout → Paint → Present`，从不经过 `Render()`
   → 运行时插入的插件 `client.js` / 动态样式表永不执行 → 界面显示「标题栏未装配（ui-titlebar）」等降级占位符。
   修法：`webkit/webview.go` 暴露 `FlushFrameBoundaryResources()`，`app/host.go` 主循环每帧调用。
3. 外壳启动即 `Focus()` 置顶（否则窗口可能被其它窗口遮挡，用户以为「没启动」）。
4. **flex `auto margin` 独吞后续兄弟空间**（`engine/layout/flexformattingcontext.go` auto 主轴外边距分支）：
   `rem := cw - (mainPos-cx) - it.finalMainSize` 未扣除**后续兄弟**的外盒与间距 → 状态栏
   `justify-content:space-between` + 中间项 `margin:0 auto` 时，中间项被推到容器右内边缘（1592），
   右侧项再被间距推成 **x=2219（视口外）** → 窗口里底部状态栏右段
   「已连接 · 本地 / UTF-8 / 上下文 0 / Midnight」**完全不可见**（浏览器同页面正常右对齐，x≈右内边缘）。
   修法：扣除后续兄弟主轴占位（`restMain`；auto margin 项位于末尾时 `restMain=0`，原行为不变）。
   验收：`.status-right` 由 `2219` → **`1353`**（= 1600-8-239，与浏览器右对齐一致）；
   新增回归用例 `webkit/flex_spacebetween_test.go`。

| # | 缺陷 | 现象（修复前 → 修复后） | 根因 |
|---|---|---|---|
| 1 | 几何 API 未传播**祖先** transform | 顶栏导航胶囊 `getBoundingClientRect().x` **640 → 534**（浏览器 534）；凡依赖 rect 的定位/测量/拖拽全部错位 | 几何路径只应用元素**自身** transform；已改为沿祖先链逐层映射 `p = A.pos + M_A(p − A.pos)` |

## 第四批：监督者指令轮 2（把已复现缺陷修掉）

### ✅ 输入闭环（最高优先）—— 已修复并通过验收

**真因（引擎缺陷，三条路径叠加）**：

1. `handleCharInput`（GLFW Char 路径）：contenteditable 无 DOM Selection 时 `InsertTextAtSelection` 失败 → 丢弃字符；
2. `applyContentEditableCharInput`（IME CharInput 路径）：同样 `return` 丢弃字符（且不派发 input）；
3. **真正的主路径是 `applyContentEditableCompositionUpdate`**：真实键盘字符在 Windows 上经 IME 以**组合事件**抵达（引擎日志 `ce-compose update="hello" from=0 len=0`），而组合开始处 `TextOffsetOfSelection(el)` 失败时把 `imeCompRoot` 置 nil → **组合文本永不写入 DOM**（`ReplaceTextRange` 从未执行，故 `len` 恒为 0）。

**修复**：

- 新增 `bindings.AppendTextToContentEditable`：无有效 selection 时把字符追加到 contenteditable **内容末尾**（浏览器语义：聚焦后字符必须进入文档），并同步 `sstate.ranges` 供连续输入；
- 新增 `bindings.SelectionInsideElement`：selection 必须**属于目标元素**才算有效 —— `sstate.ranges` 是全局单例，会残留终端 textarea / 上次 CM6 光标等**别处**的 selection（此时插入会成功但落到别处，目标框仍为空）；
- 组合起点在无 selection 时取「内容末尾 rune 偏移」而非放弃写 DOM（后续 update 替换同一范围，不累积重复）。

**验收证据**（真实窗口 + OS 级注入，`tmp/p1-evidence.log`）：

```

       "inputDetail":"len=5 htmlLen=5 kids=1 txt=\"hello\""}
```

**单测**：`app/contenteditable_input_test.go` —— `TestContentEditableCompositionWithoutSelection`（IME 组合）、`TestContentEditableCharInputWithoutSelection`（CharInput）均 PASS。

### ❌ 滚轮未上溯到可滚祖先 —— 未闭环（修复已回滚，避免回归）

- 现状（evidence）：设置面板可滚容器 `div.modal-content:0/422`，滚轮后 `scrollTop` 仍为 **0**。
- 尝试的修复：`FindScrollContainerForNode` 改为「跳过内容未超出的候选、继续向上找真正可滚的祖先」（浏览器 scroll chaining），判定用 `ScrollRange`。
- **结果与回滚**：层化面板场景下 `ScrollRange(box)` 对 `.modal-content` 返回 **0** → 所有候选被跳过、滚动目标变 **nil** → **连 DOM wheel 事件都不再派发**（evidence：`ev:scroll` 由 7 个降为 0），比原行为更差 → **已回滚为原行为**。
- 结论：本项**未闭环**。正确修复需渲染层「层化 / `position:fixed` 盒子的滚动范围」语义配套（`BoxContentSize` / `ScrollRange` 对层化盒子的口径统一）。用例 `webkit/scroll_chaining_test.go` 保留并 `t.Skip`，供后续修复时启用。

**根因（两套口径不一致）**：`BoxContentSize`（`engine/rendering/renderview.go`）递归时对**任何 overflow 非 visible 的子盒一律跳过其子树**：

```go
if st := cb.Style(); st != nil && overflowClipsContentStyle(st) {
    return // content clipped: do not recurse into this subtree
}
```

→ 外层容器（设置面板 `.modal-content`，其子盒 `.settings-content` 声明 `overflow:auto`）的内容尺寸塌成可视高 → `ScrollRange.maxY = 0`、`VerticalScrollbarMetrics.OK = false` → **既不滚动、也不绘滚动条**，而 DOM 侧 `scrollHeight − clientHeight = 422` 明确显示内容超出。

**修复（改口径本身，未动 `needsScrollbars` 阈值）**：跳过条件改为「仅当该子盒**自身真的可滚**（内容超出它自己的可视区）时才跳过其子树」，否则继续递归（溢出内容属于外层滚动区域）；并把 `FindScrollContainerForNode` 的 scroll chaining 判定统一走 `ScrollRange`（与滚动条绘制、`scrollTop` 赋值同一口径）。

**验收状态**：

- ① **单测 ✔**：`webkit/scroll_chaining_test.go` —— `TestLayeredOverflowAutoScrollRange`（层化 `overflow:auto` 内容超出 → `maxY>0` 且 `VerticalScrollbarMetrics.OK=true`）与 `TestScrollTargetSkipsNonScrollableAncestor`（**已去 Skip**）均 PASS。
- ② **真实窗口 ❌ 未闭环**：设置面板打开后滚轮，`.modal-content` 的 `scrollTop` 仍为 **0**。

## 第十批：状态属性变更的样式失效统一（2026-09-28）

用户反馈：桌面端「复选框 / 开关」点了没反应（外观不变、`v-model` 不同步）。排查发现是
**状态属性（`checked` / `open`）变更后不触发样式失效**这一类问题，共三条互相独立的断点——
浏览器不会出现，因为 JS setter 与引擎内部走的是同一条失效管线。

| # | 断点 | 现象 | 修法（wb-ui） |
|---|---|---|---|
| 1 | 引擎 `SetChecked` 与 JS `el.checked` setter **只改属性位、零失效** | `input:checked` 的 computed style 不变；`el.checked = true` 完全无效果 | `engine/html5/input.go`、`engine/js/bindings/lazyelement.go`：状态变更后走统一失效入口 |
| 2 | 失效范围只清 **el 子树**，`input:checked + span` 这类**兄弟 / 后继组合器**漏掉 | 开关的 track 停在旧底色（`input:checked + .pp-switch-track` 不生效） | 渲染桥内把失效范围扩到**父级 + 兄弟**（`webkit/webview.go`） |
| 3 | `setAttribute` / `removeAttribute` / `toggleAttribute` 未按属性分流 | `el.setAttribute('checked', …)` 不改样式（Vue 模板 / 第三方库常用写法） | `engine/js/bindings/dom.go` 按属性名分流到对应失效入口；`engine/js/bindings/dialog.go` 补同款分流 |

配套两处结构收敛：

- 「状态属性 → 样式失效」下沉为**统一入口**（`engine/html5/details.go` 的 `InvalidateStyle` 钩子），
  `input.go` / `select.go` / `details.go` 共用；
- 新增 `webkit/forminteract.go`，把「复选框 / 单选框切换 + `<label>` 点击转发 + select 弹层」
  收敛为**唯一实现**，`app.Host` 与 `webkit.Interaction` 只剩薄壳转发——此前两边各一套同名实现且已漂移
  （label 转发切 radio 时不同组互斥、也不派发 `change`）。

**证据**：

- headless 三层路径（引擎 `SetChecked` / IDL setter / `setAttribute`）×（自身、兄弟）：
  `webkit/formstate_invalidation_test.go` —— `TestCheckedStateInvalidatesStyle`、
  `TestCheckedStateRepaintsPixels`（勾选后相邻色块 `rgb(7,7,7)` → `rgb(5,5,5)`）。
- **app 真实点击链路**（`host.handleClick` 的 Release 分支）：`app/host_form_state_test.go` ——
  点击 `label.pp-switch` 内的 track → `checked=true`、`change` 派发 1 次、track 像素
  `rgb(7,7,7)` → `rgb(5,5,5)`；再点一次三者全部回退。
- `<details>` 折叠：`webkit/summary_details_activation_test.go`（点击切换 `open` + 正文盒子跟随）。

**回归口径**：

```
go test ./... -count=1        # wb-ui，需 CGO_ENABLED=1
→ 28 包 ok / 0 失败（webkit 4.46s、app 0.46s、bindings 2.12s）
```

**遗留（本轮新发现，不属本轮范围）**：引擎的 inline 布局**不给 inline 级元素建 box**——
`label` / `span` 直接挂在 `<body>` 下时不生成盒子，`HitTest` 因此不命中它们（点击落到 `<body>`，
`<label>` 转发也就无从触发）。真实 IDE 的开关写在 flex 行内（`.field{display:flex}`），
flex 子项会被 blockify 成有盒子的盒子，所以可用；「非 flex 上下文里的 inline 可点击容器」
仍是引擎缺口。写这类夹具时必须贴近真实结构（见 `app/host_form_state_test.go` 头注释）。
