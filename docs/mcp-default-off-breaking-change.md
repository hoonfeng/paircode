# MCP 启用语义变更（Breaking）：未显式启用不再连接

- 日期：2026-09-15
- 影响范围：`config/mcp.json` / `<工作区>/.pair/mcp.json` 中「缺少 `enabled` 字段」的 MCP 服务器条目
- 变更性质：Breaking（行为变更，配置格式不变）——修复背景见下「为什么」

## 变更内容

| enabled 取值 | 旧语义（2026-09-15 前） | 新语义 |
|---|---|---|
| `true` | 启用 | 启用（连接并注册工具）——不变 |
| `false` | 禁用 | 禁用——不变 |
| **缺省（无字段）** | **默认启用** | **默认禁用（不连接）**——本次 Breaking 变更点 |

新增/批量添加的服务器（`mcp_add`、市场安装、UI 新建、`ctx.mcp.upsert`）一律**默认未启用**，
需显式启用（`mcp_enable` 工具 / UI 开关 / 配置写入 `"enabled": true`）后才连接。

## 为什么

MCP 服务器连接有真实启动成本（npx 首次拉包 5~15s/台、每台常驻子进程）。
历史事故：配置中存在一批缺省 `enabled` 的示例服务器（fetch/memory/redis/sequential-thinking 等），
每个会话启动都尝试逐台串行连接（单台超时 15s），导致会话启动卡顿与数百个残留子进程。
「添加 ≠ 启用」——显式启用才付出连接成本。

## 迁移（受影响用户如何操作）

1. 升级后首次加载配置时，日志会输出一次性告警，列出所有「因缺省 enabled 被停用」的条目：

   ```
   [MCP] N 个历史条目未显式启用（enabled 缺省），按新策略（2026-09-15：添加≠启用）已停用：xxx、yyy——如需使用请用 mcp_enable / UI 启用（写入 enabled:true 后连接）
   ```

2. 需要继续使用的服务器，任选其一恢复：
   - 对 agent 说：「启用 MCP 服务器 xxx」（调用 `mcp_enable`）；
   - 在 MCP 管理 UI 中把该服务器切为「启用」；
   - 手工编辑对应 `mcp.json`，为该条目加上 `"enabled": true`。

3. 确认状态：`mcp_list`（agent 工具）会标注「禁用（未显式启用）」的条目。

## 回退

本变更无全局开关。若要恢复某条目的旧行为（开机即连），显式写入 `"enabled": true` 即可——
显式语义取代了原来的隐式默认，不会再有第三种状态。

## 配套修复（同批次）：连接池化

「默认禁用」是止血；显式启用后的连接管理本身也在同批次修复（`internal/agent/mcp.go`）：

1. **并行连接**：多台服务器并发建立（原逐台串行，N 台 × 15s 超时叠加卡住会话启动）；
2. **连接复用**：按「配置指纹」（名+命令+参数+环境变量）跨会话缓存连接——同一配置只 spawn 一次
   子进程，后续会话直接复用（注册耗时从百毫秒级降到毫秒级）；
3. **空闲回收**：连接空闲超过 TTL 自动关闭子进程（连接对象保留，下次使用按需重连）——防泄漏；
4. **退出清理**：Ctrl+C / SIGTERM 退出时统一回收池内全部连接；强杀（任务管理器）不触发清理，
   由「空闲回收」兜底 + 子进程随 stdin EOF 级联退出；
5. **失败负缓存**：起不来的服务器 30s 冷却期内不重复重试（避免每会话白等 15s 超时）；
6. **全程可见日志**：每台失败原因、注册汇总耗时、新连接 / 重连 / 回收均有日志（原 15s 超时静默跳过）。

### 运维环境变量

| 环境变量 | 默认 | 说明 |
|---|---|---|
| `PAIR_MCP_IDLE_TTL_SEC` | 600（10 分钟） | 空闲连接回收阈值（秒）；≤0 禁用空闲回收（连接常驻） |
| `PAIR_MCP_REAP_SEC` | 60 | 空闲回收扫描周期（秒，最小 1） |
