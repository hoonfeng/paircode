# 发布包拆分：web 版 / GUI 版各自独立（2026-10-19）

## 1. 问题

v1.6.22 之前每个平台只出一个 zip，包内**同时**包含两个可执行文件：

| 旧包内文件 | 大小（raw） | 用途 |
|---|---|---|
| `PairCode.exe` | 72.8 MB | GUI 单文件启动器（payload 已内嵌 pair.exe + Skia + 插件/前端） |
| `pair-server.exe` | 39.8 MB | 服务端可执行文件（纯 web 模式） |

两者是同一份 Go 程序的两种构建形态，互相重复约 40MB；再加上 `models/`（91.5MB raw）
后，旧包压缩体积 106.9MB，用户下载后无法区分「我要的是服务端还是桌面端」。

## 2. 新结构：6 个独立包

| 包名 | 主程序 | 内容要点 | 不含 |
|---|---|---|---|
| `PairCode-web-<ver>-windows.zip` | `pair-server.exe` | 插件、前端产物、`plugins-src`、`bin/config/{models.json,onnx}`、`models/`（语义搜索模型）、文档/图标 | GUI 主程序、`libSkiaSharp*` |
| `PairCode-web-<ver>-linux.zip` | `pair-server` | 同上（Linux ONNX 库） | 同上 |
| `PairCode-web-<ver>-darwin.zip` | `pair-server` | 同上（macOS ONNX 库） | 同上 |
| `PairCode-gui-<ver>-windows.zip` | `PairCode.exe` | 单文件启动器（首次运行释放 pair.exe + Skia + 插件/前端到用户级 runtime 目录）、文档/图标 | `pair-server`、独立 Skia 库文件 |
| `PairCode-gui-<ver>-linux.zip` | `PairCode` | 同上 | 同上 |
| `PairCode-gui-<ver>-darwin.zip` | `PairCode` | 同上 | 同上 |

本机（Windows）实测体积：

- `PairCode-web-1.6.22-windows.zip`：**79.2 MB**（296 条目）
- `PairCode-gui-1.6.22-windows.zip`：**28.2 MB**（46 条目）

> GUI 包不含 `models/` 的原因：启动器把 payload 释放到
> `%LOCALAPPDATA%\PairCode\runtime\<version>\` 并以该目录为工作目录启动主程序，
> 旧包放在 zip 顶层的 `models/` 从未被读取（`findModelDir` 只看 exe 同目录的
> `models/`），因此删除它不改变行为，只是去掉无效体积。

## 3. 实现

- `scripts/packager/main.go`：`DistConfig.Editions []DistEdition`，`execPackage` 遍历
  `edition × target`；`mainSrc` 按平台后缀解析 release/ 下主程序，包内改名 `mainDst`；
  `nativeOnly`（gui，cgo）只打本机平台；zip 命名 `<dirName>-<version>-<goos>.zip`。
- `packager.json`：`dist.include` 保留公共条目，`dist.editions` 定义 web / gui 两份。
- `.github/workflows/release.yml`：每个平台 job 上传 `release-web-<os>` 与
  `release-gui-<os>` 两个 artifact；`publish-release` 以 `release-*` 合并后上传 6 个 zip。
- `scripts/verify-package-contents.mjs`：默认校验 6 个 zip；新增发行版隔离断言
  （web 包必须含 `pair-server[.exe]`、不得含 `PairCode[.exe]`/`libSkiaSharp*`；
  gui 包反之）。

## 4. 验证

### 4.1 本地构建与打包（Windows，2026-10-18）

```
packager --targets windows/amd64 --step build-go      # pair-server.exe
packager --step build-go-gui                          # pair.exe (cgo)
packager --step stage-gui-runtime                     # libSkiaSharp.dll
packager --step build-stub                            # PairCode.exe
packager --targets windows/amd64 --step package       # 两个 zip
```

### 4.2 web 包运行验证

解压到 `_temp/pkgtest/web`，`WEB_PORT=9096 ./pair-server.exe`：

- 日志：`[WebUI] 使用外部前端目录: ...\.pair\assets\runtime\web`、`Web 服务已启动 (端口 9096)`
- `GET /` → **200**（21080 字节，返回 index.html）
- `GET /favicon.svg` → **200**（1030 字节）

> 首次测试用 9097 端口时返回 404：该端口被 `wxbridge.exe`（微信桥，绑定
> `127.0.0.1:9097`）占用，比 pair-server 的 `0.0.0.0:9097` 更具体而优先命中。
> 换 9096 后正常。后续验证请先 `netstat` 确认端口空闲。

### 4.3 GUI 包运行验证

解压到 `_temp/pkgtest/gui`，`WEB_PORT=9095 ./PairCode.exe`：

- 窗口正常打开（1600×1000，标题 `PairCode IDE`）
- `[fontmgr] cjk=Noto Sans SC`、`loaded 61 system font(s)`
- `GET /` → **200**（21080 字节）
- 截图 `screenshots/v1622_gui_pkg_9095.png`：侧栏「会话 / 暂无对话 / 基础 · 7 插件」、
  欢迎面板中文全部正常，无白屏、无方块

### 4.4 内容断言

```
node scripts/verify-package-contents.mjs release/PairCode-web-1.6.22-windows.zip release/PairCode-gui-1.6.22-windows.zip
```

- web：296 条目，`.smoke=0 .git=0 node_modules=0 .pair/tasks=0`，含 `pair-server.exe`，
  无 `PairCode.exe`、无 `libSkiaSharp*`
- gui：46 条目，无禁入内容，含 `PairCode.exe`，无 `pair-server.exe`

### 4.5 未受影响

- 9090 安装目录实例全程 `http=200`（未重启、未改动）。
- `libSkiaSharp.dll` 仍只进入 GUI 启动器的 payload（不再作为包内独立文件）。

## 5. 生效范围

本结构随本提交生效。v1.6.22 已发布的 Release 资产仍是旧形态（旧 zip 里两个 exe）；
下一个 tag 触发的 `release` 流水线将产出 6 个独立 zip。
