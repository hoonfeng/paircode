# 缺陷清单（事件响应 > 内容加载 > 组件样式）

> 每条五要素：**现象 / 最小复现 / 期望（浏览器） / 实际（引擎） / 所属域**。
> 已修条目注明回归测试名。

## 【事件响应】E1 顶栏导航胶囊切换后的视图与高亮同步
- **现象**：点击顶栏「编辑器/市场」胶囊，视图切换与 `.active` 高亮是否同步。
- **最小复现**：`<button class="tb-nav-pill">A</button><button class="tb-nav-pill active">B</button>`，点击 A 后读 `.tb-nav-pill.active` 文本与 `document.activeElement`。
- **期望（浏览器）**：仅被点项带 `.active`，主区视图同步切换。
- **实际（引擎）**：**已修** —— 根因在 `engine/js/bindings/dom_events.go`：`jsListener.HandleEvent` 把回调的 `this` 固定绑为 `jsc.Undefined()`（旧注释误以为「plain call」就是浏览器语义）；DOM 标准 inner invoke 规定「监听器是 Function 且事件 `currentTarget` 非 null 时 **this = currentTarget**」。修复前被点胶囊拿不到 `.active`（实测快照 `点击 p1 后 = active=count=0 | view0.display=block | view1.display=none`）；修复后 `active=p1 | view0.display=none | view1.display=block`。
- **所属域**：事件响应 ｜ 状态：**已修**（`webkit/nav_pill_sync_test.go`：`TestTopNavPillSwitchSync`）

## 【事件响应】E2 菜单展开/收起与子项点击穿透
- **现象**：顶栏「帮助」菜单展开后点击菜单项，是否被下层元素截获。
- **最小复现**：展开 `.menu-dropdown` 后点击 `.menu-item`，读 `document.elementFromPoint(中心).className`。
- **期望（浏览器）**：命中 `.menu-item`；收起后命中下层。
- **实际（引擎）**：**经最小复现确认为非缺陷**。复现步骤：容器 `position:relative`，其内放下层 `#under`（300×200）与展开菜单 `#menu`（`position:absolute;left:20;top:20;z-index:10`，含 `#i1/#i2` 两项）；先读 `document.elementFromPoint`（菜单项中心 / 菜单外），再真实点击 `#i1` 中心并读事件序列。实测证据：`命中测试 = item1Area=i1 item2Area=i2 outsideMenu=under`、`点击后事件序列 = "i1"`（未穿透到下层 `#under`）。
- **所属域**：事件响应 ｜ 状态：**非缺陷（含实测证据）**（`webkit/menu_hit_test.go`：`TestMenuDropdownClickHitsTopmostItem`）

## 【事件响应】E4 嵌套可滚容器的滚动链
- **现象**：滚轮落在内层不可滚容器上时是否上溯到最近真正可滚的祖先。
- **最小复现**：外层 `overflow-y:auto` + 内层 `overflow-y:auto`（内容不超出），滚轮后读外层 `scrollTop`。
- **期望（浏览器）**：外层 `scrollTop > 0`。
- **实际（引擎）**：**经最小复现确认为非缺陷**。复现步骤：外层 `#outer`（150×100，`overflow-y:auto`，`scrollHeight=330 > clientHeight=100`）+ 内层 `#inner`（100×30，`overflow-y:auto`，内容 20 不超出）；`HandleMouseMove(50,15)` 把光标移入内层后 `HandleWheel(-120)`，读两者 `scrollTop`。实测证据：滚轮后 `outer.scrollTop > 0`、`inner.scrollTop = 0`（正确上溯到可滚祖先）。★ 注意 `Interaction.Wheel` 的 `deltaY` 是 Win32 语义（`正=向上滚`，`step=-deltaY/120*48`）——首版测试误传 `+120`（顶部继续上滚被 clamp 为 0）造成「不滚动」的假象，属测试参数方向错误而非引擎缺陷。
- **所属域**：事件响应 ｜ 状态：**非缺陷（含实测证据）**（`webkit/nested_scroll_chain_test.go`：`TestNestedWheelChainsToOuterScrollable`；`webkit/scroll_chaining_test.go` 两个既有用例继续通过）

## 【事件响应】E5 contenteditable 退格（Backspace）完全不生效
- **现象**：在手写 `contenteditable`（只监听 `input`/`keydown`、从不调用 selection API）中键入字符后按退格，DOM 文本毫无变化。
- **最小复现**：`<div id="ed" contenteditable="true">` 聚焦后键入 `"hello"`，再连续退格 3 次，读 `ed.textContent`。
- **期望（浏览器）**：`"he"`（len=2）。
- **实际（引擎）**：**已修** —— 两层根因：① `app/host.go` 的 `deleteFocusedChar` 走 `setFocusedElementValue`，而该函数对 `contenteditable` **直接 return**（保护 CodeMirror 6 的结构化 DOM，本身是正确的设计）→ 手写 contenteditable 的退格无处落地；② `sstate.ranges` 是 bindings 包级单例、跨 WebView 复用，残留的旧页面 range 使 `SelectionInsideElement` 误判为「有有效选区」→ 走失效的旧路径（同包全量测试 FAIL、单独跑 PASS 的差异源）。修复：新增 `bindings.DeleteCharFromContentEditable`（无 Selection 时删除内容末尾一个字符，与字符输入的 `AppendTextToContentEditable` 对称），并把 `SelectionInsideElement` 严格化为「起点节点必须仍 `IsConnected()`」（陈旧/分离节点的 range 一律无效）。实测：修复前 `退格 3 次后 textContent="hello" (len=5)`；修复后 `textContent="he" (len=2)`。
- **所属域**：事件响应 ｜ 状态：**已修**（`app/input_backspace_test.go`：`TestInputBackspaceIntoDOM`）

## 【事件响应】E6 `element.click()`（程序化点击）未实现
- **现象**：JS 调用 `el.click()` 抛 `TypeError: Object has no member 'click'` → 菜单项 / tab / 自定义控件 / 「点击外部关闭」等程序化触发链路整条不可用。
- **最小复现**：页面加载后执行 `document.getElementById('btn').click()`（`#btn` 注册了 click 监听器，`#parent` 注册冒泡监听），读事件日志字符串。
- **期望（浏览器）**：监听器被调用且 `this === btn`、`e.type === 'click'`、`bubbles === true`、`cancelable === true`；事件冒泡到 `#parent`（收到 `target=btn, currentTarget=parent`）。
- **实际（引擎）**：**已修** —— 元素方法表（`engine/js/bindings/lazyelement.go`）缺失 `click` 成员；新增实现：向元素自身派发 `dom.NewMouseEventFromInit(dom.EventClick, {Bubbles:true, Cancelable:true, Button:dom.MouseButtonLeft, Detail:1})`。实测证据：修复后 `btn:this=btn:type=click:bubbles=true:cancelable=true | parent:target=btn:currentTarget=parent`。（该缺陷由 IDE 桌面端 headless 复核注入 `d.click()` 时暴露。）
- **所属域**：事件响应 ｜ 状态：**已修**（`webkit/element_click_api_test.go`：`TestElementClickDispatchesMouseEvent`）

## 【组件样式】S1 `getComputedStyle(el).display` 返回 undefined
- **现象**：级联未声明 display 的元素读 display 为 `undefined`。
- **最小复现**：`<span id="plain">` 与 `<span id="b" hidden>`，分别读 `getComputedStyle(el).display`。
- **期望（浏览器）**：`"inline"` / `"none"`（恒为字符串）。
- **实际（引擎）**：**本轮已修** —— `getComputedStyle` 增 display 回退（hidden → `"none"`；块级 → `"block"`；可替换/表单 → `"inline-block"`；其它 → `"inline"`）。
- **所属域**：组件样式 ｜ 状态：已修（`webkit/computed_display_test.go`：`TestComputedStyleDisplayAlwaysResolved`）。

## 【组件样式】S6 `getComputedStyle` 简写未展开为长写（overflow / border）
- **现象**：声明 `overflow:auto` 后读 `cs.overflowX` 得 `undefined`；声明 `border:2px dashed #123456` 后读 `cs.borderTopStyle` 得 `undefined`（浏览器恒有值）。
- **最小复现**：`<div id="box" style="width:120px;height:40px;overflow:auto;border:2px dashed #123456;border-left-width:5px">`，读 `getComputedStyle(box).overflowX` / `.overflowY` / `.borderTopStyle` / `.borderRightStyle`。
- **期望（浏览器）**：`"auto"` / `"auto"` / `"dashed"` / `"dashed"`（简写展开；**属性访问与 getPropertyValue 双路**都有值）。
- **实际（引擎）**：**本轮已修** —— 新增 `expandOverflowShorthand`（overflow → overflow-x/y，单值/双值语义）与 `expandBorderStyleLonghand`（border/border-style → 四向 style+color）；白名单补 40 个长写属性（`borderTopStyle`/`borderTopColor`/`alignSelf`/`flexWrap`/`flexGrow`… 此前只有 `borderTop`/`borderStyle`）。
- **所属域**：组件样式 ｜ 状态：已修（`webkit/computed_readapi_test.go`：`TestComputedShorthandExpansion`，实测 `overflow-x=auto(gpv:auto) border-top-style=dashed(gpv:dashed) border-left-width=5px`）。

## 【组件样式】S7 `getComputedStyle` 对未声明属性不返回 CSS 初始值
- **现象**：未声明 `font-size`/`line-height`/`font-weight`/`pointer-events`/`min-width`/`max-width` 时，`cs.fontSize` 与 `cs.getPropertyValue('font-size')` 均为 `undefined`/`""`；浏览器对**每个属性恒有值**。
- **最小复现**：`<div id="plain" style="width:80px;height:20px">plain</div>`，读 `cs.fontSize` / `cs.lineHeight` / `cs.fontWeight` / `cs.pointerEvents` / `cs.minWidth` / `cs.maxWidth` / `cs.boxSizing` 及对应 `getPropertyValue`。
- **期望（浏览器）**：`16px` / `normal` / `400` / `auto` / `auto` / `none` / `content-box`（双路一致）。
- **实际（引擎）**：**本轮已修** —— 新增 `uaInitialComputedValues`（50+ 项 CSS 初始值表）；属性访问路径（白名单循环 `else` 分支）与 `getPropertyValue` 路径**双双回退**；仅在 JS 对象层生效，不改 `computedStyleFor` 的 map（避免影响布局与继承链计算）。
- **所属域**：组件样式 ｜ 状态：已修（`webkit/computed_readapi_test.go`：`TestComputedInitialValueFallback`，实测 `font-size[16px/16px] pointer-events[auto/auto] min-width[auto/auto] max-width[none/none]`）。

## 【渲染绘制】R1 帮助菜单展开后面板不可见（层已遍历却不产出可见像素）

## 【渲染绘制】R2 SVG 渐变填充的圆角矩形丢失圆角与描边
- **现象**：关于弹窗 logo（内联 SVG）在**浏览器里是带圆角的深色方块 + 较亮描边轮廓**，
  桌面壳里却只剩尖括号与中心光点 —— **圆角底色块与描边整体不绘制**。
- **根因（`engine/rendering/svg.go`）**：`svgFilledShape.paint` 的**渐变填充分支提前
  `return`**，直接跳过其后的 stroke 绘制 ⇒ 描边永不出现；且 `paintGradientOnShape`
  **不接受 rx/ry**，只按直角矩形铺渐变 ⇒ 即便是圆角 rect，渐变也溢出到圆角之外。
- **修复**：①渐变分支不再提前返回，补齐 stroke；②`paintGradientOnShape` 增加
  rx/ry 参数并按圆角裁剪；③原先靠 `return` 触发的 `defer canvas.Restore()` 改为
  **立即 Restore**，防止 canvas 状态泄漏。
- **验证证据**：新增回归 `engine/rendering/z_svg_gradient_rect_test.go`
  （`TestSVGGradientRectKeepsRoundedCornersAndStroke`）。**回退修复后精确失败**于
  `corner (12,12) = #0007f7, want transparent (渐变须被 rx 圆角裁剪)`，
  证明断言有效；修复后通过。全量回归 6/6 绿：
  layout 0.747s / rendering 0.660s / css cached / bindings 1.620s / webkit 4.161s / app 0.468s。
- **注**：真实窗口截图中该 logo 的圆角块与描边**对比度很低**（填色 `#0a1628→#0d1f2e`、
  描边 `#1a3a4a`），肉眼不易分辨 ⇒ 本条的**可信证据是引擎级回归测试**，不依赖目视。
- **所属域**：渲染绘制（SVG） ｜ 状态：**已修复 · 回归测试锁定**
