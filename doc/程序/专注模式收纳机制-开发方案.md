## 一、背景与目标

### 1.1 问题（用户发现）

上轮修复（`4fa3e367`：Ctrl+K 专注模式纳入右栏统计栏与底部面板）后，用户提出根本性问题：

> **「以后如果更新再增加组件，会自动处理吗（被专注模式收纳）？」**

code 级核查结论：**不会**。专注模式的收纳是**枚举白名单**，不是通用兜底——

| 机制层 | 现状（证据） | 缺口 |
|---|---|---|
| 收纳执行 | `ui-state.js` `setFocusMode` 显式列出 4 项（sidebar/convList/statsRail/bottomPanel，行 406-427） | 无「其余全隐」逻辑；新面板不登记 = 不收 |
| 布局列宽 | `ShellApp.vue` `gridStyle` 显式枚举（`48px | sidebarW | 1fr | railW`，行 332-348） | 新网格列必须手动登记列宽 |
| 先例 | 右栏 StatsRail：上游 v1.6.7 引入时**加了网格第 4 列但没同步 setFocusMode** → 专注模式视而不见 → 本轮人工补上 | 「上游加组件会顺手维护专注收纳」假设**已被证伪** |
| 流程 | source-update 更新流程（merge→build→deploy）**无任何 UI 回归检查** | 上游新增区域漏收纳时，**没有任何自动发现机制** |

同时核查发现第 5 个现存缺口：`rightPanelVisible`（对话面板渲染/保活开关，`ShellApp.vue` 56/59 行对话容器 `v-if` 条件）不在收纳清单——若用户曾关闭对话面板（`rightPanelVisible=false` 持久化），进入专注（纯对话）时主区**空白**。

### 1.2 目标（三项改进）

1. **登记表驱动**：`setFocusMode` 收纳清单由散列改为**数据表**（`FOCUS_PANELS`），新增面板 = 表里加一行；登记规则写入注释（`ui-state.js` + `ShellApp.gridStyle` 两处）。
2. **专注收纳探针（自动告警）**：新增 `scripts/source-update/focus-probe.mjs`，headless 快照对比，**自动列出「专注后仍占空间且不在恒显白名单内」的区域**；接入更新流程（部署成功后自动跑，告警不阻断）。
3. **「纯对话」语义闭环**：进入专注自动**切回对话视图**；退出专注**还原**进入前视图（与四周面板「记忆→收起→还原」体系一致）；专注态内主动切到非对话视图 = 退出专注。

### 1.3 现状机制解析（2026-09-25 代码核查）

- `focusMode` 全库消费点 25 处 / 5 文件（`ui-state.js` 唯一权威入口 + app-actions/MenuBar/EditorArea 等调用方）。
- 网格直系区域（`.app-root` children）：`.plugin-area-titlebar`（跨列顶栏 40px）｜`.plugin-area-activitybar`（活动栏 48px）｜`.plugin-area-sidebar`（col 2）｜`.main-area`（col 3，内含对话/编辑器/市场/工具集/插件视图 pane，`v-show` 按 `state.panels.mainTab` 切换）｜`.right-rail-host`（col 4，288px）｜`.app-statusbar-host`（跨列底栏 28px）｜`.modals-host`（fixed 浮层）。
- 恒显骨架（专注不处理）：titlebar / activitybar / main-area / statusbar / modals。
- 可收纳（专注处理）：sidebar / right-rail / （主区内）.conv-sidebar、.bottom-panel 等语义字段控制；**新增**：rightPanelVisible（对话面板本体）。
- 主区视图：`state.panels.mainTab` 是单一事实源（`'conversation' | 'editor' | 'market' | 'toolsets' | 'view:<插件>:<id>'`）；编辑者 openEditor / 关闭 closeEditor / 顶栏胶囊 setMainView / 插件视图 activateViewTab 等路径**均不检查 focusMode**（除 openEditor 的退出专注）。

## 三、机制设计

### 3.1 专注收纳：从「枚举散列」到「登记表」

```
┌──────────────── 专注收纳登记表（FOCUS_PANELS，ui-state.js）─────────────────┐
│  key                  fold（专注态取值）   label                              │
│  ────────────────────────────────────────────────────────────────────────  │
│  sidebarVisible       false               左栏（文件/搜索/Git）              │
│  convListVisible      false               会话列表面板                       │
│  statsRailVisible     false               右栏统计栏（v1.6.7+）              │
│  bottomPanelVisible   false               底部面板（终端）                   │
│  rightPanelVisible    true ★           对话面板（纯对话必须显示）          │
│  panels.mainTab       'conversation' ★   主区视图 tab（切回对话）            │
└────────────────────────────────────────────────────────────────────────────┘
      进入专注：focusSaved = 6 项现场快照 → 逐项 set(fold)
      退出专注：逐项 set(focusSaved 原值) → focusSaved = null
      专注态内 toggle：syncFocusTarget(key) 更新该 key 的还原目标
```

**★ 登记规则（写入代码注释）**：新增常驻区域/面板时——
1. 在 `FOCUS_PANELS` 登记一行（fold = 专注态取值）；
2. 若占用网格列，同步 `ShellApp.vue` `gridStyle` 列宽公式；
3. 跑 `focus-probe` 探针验证（更新流程自动跑 + 手动 `node scripts/source-update/focus-probe.mjs`）。

### 3.2 纯对话语义闭环

```
进入专注（Ctrl+K）                     退出专注（Ctrl+K）
┌────────────────┐                  ┌────────────────┐
│ 记忆 6 项现场    │                  │ 还原 6 项现场    │
│ 收 4 面板=false  │                  │ （含 mainTab）   │
│ rightPanel=true │                  │                 │
│ mainTab→对话     │                  │                 │
└────────────────┘                  └────────────────┘

专注态内「主动切到非对话视图」→ 视为退出专注（先还原、后显式覆盖）：
  · setMainView(view≠'conversation')  → setFocusMode(false) → 设 mainTab=view
  · activateViewTab(插件视图)          → setFocusMode(false) → 设 mainTab=view:...
  · openEditor(文件)                   → setFocusMode(false) → 设 mainTab=editor（顺序上移）
  · setMainView('conversation')        → 保持专注（对话=专注本色）
```

### 3.3 探针：自动探测未收纳区域

```
focus-probe.mjs 流程：
  ① 启动 headless Edge（独立 profile，CDP 端口，可 --web-port/--cdp-port 指定）
  ② 打开 http://127.0.0.1:<web-port>/ → 等壳就绪（__state/.app-root/.conversation-container）
  ③ 基线快照：枚举 .app-root 直系子元素（class + 占位矩形）+ 关键 state
  ④ Ctrl+K 进入专注 → 快照
  ⑤ 判定：
     · state 检查：4 面板=false、rightPanelVisible=true、mainTab='conversation'
     · 直系枚举（通用兜底）：非白名单元素「专注前占空间 且 专注后仍占空间」→ UNCOLLECTED 告警
       （白名单 = 恒显骨架：titlebar/activitybar/main-area/statusbar/modals）
     · 对话容器仍可见（纯对话断言）
  ⑥ Ctrl+K 退出 → 还原校验（state 与直系元素尺寸复原）
  ⑦ 关闭浏览器 → 输出：PASS / WARN(未收纳清单) / ERR
  exit：0=通过 / 3=发现未收纳（告警级） / 9=脚本异常

接入更新流程（update.mjs，deploy 成功之后、finish 之前）：
  · 动态 import focus-probe → runFocusProbe({ webPort: 9090, log })
  · 任何异常 catch → 仅告警，不改变更新结果（Q2：不阻断）
  · 探针结论写入 state.focusProbe → last-result.json / update.log
```

### 3.4 白名单与误报策略

- 白名单为「恒显骨架」五个宿主类名，写死在探针（与 `ShellApp.vue` 模板/CSS 对应），**宁可误报不可漏报**（告警不改代码，人工判断）。
- 探针 3（UNCOLLECTED）为**告警级**：更新流程中不阻断；人工看到后按 §3.1 登记规则处理。

## 七、明确不做

1. **不做 CSS「白名单兜底隐藏」**：对新增网格列无效（列宽由 `gridStyle` 模板定义），且可能过度隐藏；留待探针实践后再评估。
2. **不改现有 4 面板已验证的收纳行为**（回归保护）。
3. **探针不阻断更新**（告警级）。
4. **不动恒显骨架**（顶栏/活动栏/状态栏/modals）。
5. **不处理极端组合**「专注态内正激活的插件视图被卸载 + 退出还原」——由 `refreshViews` 兜底 + `syncFocusTarget` 缓解，不做专门机制。
6. **不修** `EditorArea` 右键菜单「命令面板」label 与实际动作（打开搜索栏）错位——另案（与本主题无关）。
7. **不推送上游**（未获「更新到网上仓库」指令，仅本地提交）。

| 构建/部署风险 | 中 | 独立实例 9098 先行全量验证；deploy-pair-full.ps1 自带备份+sha256+失败回滚 |

**回退方案**：① 代码级——本轮改动集中在 `ui-state.js`（单一提交）可单独 revert；② 部署级——deploy-pair-full 自带失败回滚 + 备份目录；③ 行为级——探针告警不满足可先忽略（不影响更新）。
