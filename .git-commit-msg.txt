fix: desktop ws-list renders via mount-time preload (goja reactivity gap)

Root cause (log-proven): in wb-ui's goja-based Vue 3.5 runtime, the render
effect does NOT collect dependencies for whole-array assignment on
state.wsList — watch() fires (len=5) but v-for/v-if never re-render
(data-wslen stayed 0 while data-wf=4). FileExplorer showed "暂无工作区"
while the backend /api/settings returns 5 recentProjects.

Fix: App.vue setup (before mount) synchronously preloads wsList via
go.bridge_call (desktop mode only, window.__DESKTOP_MODE__) so the FIRST
render already reads 5 items and v-for builds the ws-item list. Browser
mode keeps the async loadWsList path (native reactivity works there).
FileExplorer wraps wsList in a computed for template consistency.

Verified in desktop window logs: wsItems:5, wsEmpty:0, wsNames:
["gou-ide","wb-ui","数据采集标注&agent","GWui","图文视频agent"], ws-active
on the current workspace — identical to Edge/web. Diagnostic logs removed.
