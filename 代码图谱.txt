代码知识图谱集成至Agent内部规划文档（无MCP方案）

1. 项目目标
   - 将代码知识图谱作为Agent内置的确定性记忆与推理引擎，所有图谱操作通过Agent内部API完成，不依赖任何MCP服务。
   - 支持多维度代码理解：语法结构、依赖调用、语义文档、演化运维。
   - 提升Agent在代码定位、影响分析、变更追溯、语义搜索等任务中的准确率与效率。

2. 整体架构（文字描述）
   Agent进程内部包含：
   - Agent推理引擎（LLM）：Plan -> Retrieve -> Act -> Reflect
   - 图谱查询引擎：结构化查询（Cypher/GQL）、图遍历（BFS/DFS/影响路径）、向量检索、混合检索
   - 融合知识图谱（内存+持久化）：分为四层（语法结构层、依赖调用层、语义文档层、演化运维层）
   - 图谱构建器（离线/增量）：Tree-sitter AST解析、静态分析（调用图/依赖图）、LLM语义标注、Git历史解析

   所有组件均在Agent进程内，无外部服务依赖。

3. 融合的四种知识层
   (1) 语法结构层
       - 核心实体：文件、包、模块、类、函数、方法、变量、类型
       - 核心关系：包含（文件→类→方法）、定义、继承
       - 技术：Tree-sitter AST解析
   (2) 依赖调用层
       - 核心实体：调用点、导入语句
       - 核心关系：调用（函数→函数）、导入（文件→模块）、依赖（模块→模块）
       - 技术：静态分析（call graph、import graph）
   (3) 语义文档层
       - 核心实体：文档段落、注释块、API描述
       - 核心关系：描述（文档→实体）、标注（语义标签→实体）
       - 技术：LLM嵌入、向量检索
   (4) 演化运维层
       - 核心实体：Commit、PR、Issue、部署事件、告警
       - 核心关系：引入（Commit→实体）、修复（PR→Issue）、影响（变更→运维事件）
       - 技术：Git历史解析、运维事件绑定

4. 技术选型
   - AST解析：Tree-sitter（多语言，确定性）
   - 静态分析：自研 / python_graphs / WALA
   - 图谱存储：SQLite + 内存图结构（轻量，无外部依赖）
   - 图查询：自研GQL引擎 / Cypher子集（Agent内部API）
   - 向量检索：本地向量库（LanceDB / Chroma）
   - 语义标注：代码LLM（离线/在线）
   - 增量更新：自研更新器 + Git Hook

5. 实施阶段与里程碑
   Phase 1 – 基础语法图谱（2~3周）
   - 集成Tree-sitter，支持目标语言（Python/JS/Java等）
   - 构建文件→包→类→函数→变量的结构图
   - 实现API：get_file_structure, get_function_definition, get_class_hierarchy
   - 里程碑：Agent能回答“函数定义在哪？”、“类的继承关系？”

   Phase 2 – 依赖与调用图谱（2~3周）
   - 解析导入依赖，构建模块级依赖图
   - 构建跨文件的函数级调用图
   - 实现API：get_callers, get_callees, impact_analysis
   - 增量更新：只重分析变更文件
   - 里程碑：Agent能回答“修改这个函数影响哪些地方？”、“谁依赖这个模块？”

   Phase 3 – 语义与文档层（2~3周）
   - 解析注释、docstring、README等
   - 嵌入模型（BGE/CodeBERT）向量化
   - 建立文档→实体的关联
   - 实现API：semantic_search（自然语言查询）
   - 混合检索（结构过滤+语义排序）
   - 里程碑：Agent能回答“哪里实现了支付逻辑？”、“这个函数是做什么的？”

   Phase 4 – 演化与运维层（按需，2周）
   - 解析Git历史（commit、PR、issue）
   - 关联变更与实体
   - 实现API：when_introduced, recent_changes_affecting
   - 里程碑：Agent能回答“这个bug是哪次提交引入的？”、“最近的PR影响我的模块吗？”

   Phase 5 – Agent推理集成（持续迭代）
   - 将图谱查询封装为Agent内部工具
   - 在Plan-Act循环中加入图谱检索
   - 多跳推理（图遍历）
   - 图增强RAG（图谱定位+LLM生成）
   - 性能优化：缓存、索引、并发
   - 里程碑：Agent代码理解/修复任务达到预期准确率

6. 关键注意事项
   - 图谱是“地图”而非“全书”：只存结构和元信息，源码按需从文件系统读取。
   - 确定性与LLM平衡：语法/依赖用确定性工具，语义标注用LLM。
   - 无MCP强制：所有组件进程内运行，无外部依赖，低延迟可控。
   - 从简单开始：先完成Phase 1~2，再逐步叠加，避免过度工程。

7. 成功指标
   - 代码实体定位准确率 >= 95%
   - 影响分析覆盖完整度（与手动对比）>= 90%
   - 语义搜索Top-5召回率 >= 80%
   - 查询响应时间（P95）< 200ms
   - 增量更新延迟 < 30s
   - Agent任务成功率提升（对比无图谱）>= 30%

8. 资源需求
   - 人力：1~2名后端/ML工程师（熟悉AST、图数据库、LLM）
   - 时间：约8~10周（分阶段交付）
   - 基础设施：无需额外服务器，本地运行（可选GPU加速语义嵌入）

9. 风险与应对
   - 多语言AST解析不统一 -> 用Tree-sitter统一抽象，按语言适配
   - 大型项目图谱过大 -> 按需加载+分区存储，仅加载活跃模块
   - LLM语义标注成本高 -> 仅标注关键实体（类、公共函数），用轻量模型
   - 增量更新逻辑复杂 -> 先从文件粒度，逐步精细到函数级
   - 查询性能瓶颈 -> 索引优化（B-tree、向量索引），查询缓存

10. 附录：参考案例
    - CodeGraph：Tree-sitter + SQLite，工具调用减少71%，Token减57%，速度提升46%
    - Prometheus：统一图结构覆盖7种语言，SWE-bench解决率28.67%
    - Graphify：多模态管线（AST+文档+视觉概念）
    - RANGER：仓库级细粒度图谱（变量级），支持实体和自然语言查询
